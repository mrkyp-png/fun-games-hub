# 🪱 지렁이 게임 기획서 및 게임 개발 설명서

## 1. 문서 목적

본 문서는 게임 앱에 포함되는 **지렁이 게임**의 전체 게임 규칙, 화면 구성, 조작 방식, 난이도, 먹이 시스템, 적 지렁이, 충돌, 미니맵, Emoji 완성 및 클리어 보상에 대한 최종 개발 기준을 정의한다.

Claude Code는 본 문서를 기준으로 게임을 구현한다.

문서에 명시되지 않은 기능은 임의로 추가하지 않는다.

---

# 2. 게임 기본 개념

## 2.1 게임명

**지렁이 게임**

## 2.2 핵심 콘셉트

넓은 플레이 맵을 이동하면서 맵 곳곳에 배치된 먹이를 찾아 획득한다.

먹이를 하나씩 획득할 때마다 연결된 Emoji 그림의 진행도가 올라가며, **모든 먹이를 획득하면 하나의 Emoji 그림이 완성된다.**

동시에 플레이어와 유사한 형태의 **적 지렁이**가 맵을 이동하므로 적 지렁이를 피하면서 먹이를 찾아야 한다.

## 2.3 핵심 재미

```text
넓은 맵 탐색
+
먹이 수집
+
적 지렁이 회피
+
미니맵 활용
+
지렁이 성장
+
Emoji 그림 완성
=
지렁이 게임
```

# 4. Level 구성

총 **10개 Level**로 구성한다.

Level이 올라갈수록 기본적으로:

1. 먹이 수 증가
2. 적 지렁이 수 증가

를 통해 난이도를 높인다.

---

# 5. Level별 먹이 수

Level 1은 **20개**로 시작하며 Level이 올라갈 때마다 **5개씩 증가**한다.

| Level | 먹이 수 |
| ----: | ---: |
|     1 |   20 |
|     2 |   25 |
|     3 |   30 |
|     4 |   35 |
|     5 |   40 |
|     6 |   45 |
|     7 |   50 |
|     8 |   55 |
|     9 |   60 |
|    10 |   65 |

### 핵심 규칙

**Level 1 = 20개**

**Level 2 = 25개**

**Level 3 = 30개**

...

**Level 10 = 65개**

이 값은 고정된 기본값으로 사용한다.

---

# 6. 플레이 맵

## 6.1 맵 크기

고정된 작은 맵을 사용하지 않는다.

일반적인 지렁이 게임처럼 **실제 플레이 공간이 화면보다 넓은 대형 맵**으로 구성한다.

플레이어가 이동하면 카메라가 플레이어를 따라간다.

## 6.2 맵 특징

* 화면보다 실제 맵이 넓다.
* 플레이어 이동에 따라 카메라가 이동한다.
* 맵 전체에 먹이가 분산된다.
* 적 지렁이가 맵 전체에서 이동한다.
* 미니맵으로 전체 맵을 확인할 수 있다.
* 맵의 외부 영역으로 이탈할 수 없다.

---

# 7. 카메라

카메라는 기본적으로 플레이어 지렁이를 따라간다.

플레이어가 화면 중앙에서 이동하면 카메라도 함께 이동하여 넓은 맵을 탐색할 수 있도록 한다.

카메라가 너무 빠르게 움직여 화면이 흔들리는 느낌이 발생하지 않도록 부드럽게 추적한다.

---

# 8. 플레이어 지렁이

## 8.1 기본 이동

플레이어가 터치하여 지렁이의 진행 방향을 조작한다.

## 8.2 조작 방식

모바일 터치/드래그 기반으로 구현한다.

기본 개념:

```text
손가락 드래그
↓
지렁이 진행 방향 변경
↓
지속 이동
```

별도의 방향키를 기본 UI로 배치하지 않는다.

---

# 9. 플레이어 이동 속도

플레이어 지렁이의 기본 이동 속도는 **기본적으로 모든 Level에서 동일하게 유지**한다.

난이도를 높이기 위해 플레이어 속도를 계속 증가시키지 않는다.

난이도의 핵심은:

**먹이 증가 + 적 지렁이 증가**

이다.

속도는 추후 플레이 테스트 결과에 따라 설정값으로 조정할 수 있도록 한다.

---

# 10. 지렁이 성장

플레이어 지렁이가 먹이를 획득하면 몸 길이가 소폭 증가한다.

예:

```text
게임 시작
🪱

먹이 획득
🪱🪱

추가 획득
🪱🪱🪱
```

## 성장 규칙

* 먹이 획득 시 몸 길이 증가
* 성장량은 작게 설정
* Level 하나를 진행하는 동안 지나치게 길어지지 않도록 제한
* 성장 최대값을 설정값으로 관리

지렁이 성장의 목적은 **게임의 시각적 재미를 높이는 것**이며, 지나치게 긴 몸으로 인해 조작이 불가능해지는 상황은 방지한다.

---

# 11. 먹이 시스템

## 11.1 먹이 배치

먹이는 맵 전체에 분산 배치한다.

모든 먹이가 시작 지점 주변에 몰려 있어서는 안 된다.

## 11.2 배치 원칙

* 맵 전체를 활용
* 먹이끼리 지나치게 가까운 배치 금지
* 시작 지점 주변에는 일부 먹이 배치
* 맵의 먼 지역에도 먹이 배치
* 적 지렁이 시작 위치와 겹치지 않도록 처리
* 모든 먹이는 플레이어가 접근할 수 있는 위치에 배치

---

# 12. 먹이 랜덤 배치

먹이 위치는 랜덤화할 수 있도록 구현한다.

단순한 완전 랜덤이 아니라 다음 조건을 만족해야 한다.

```text
맵 범위 확인
↓
랜덤 위치 생성
↓
다른 먹이와 최소 거리 확인
↓
적 지렁이와 충돌 가능성이 지나치게 높은 위치인지 확인
↓
플레이어 시작 위치와 적절한 거리인지 확인
↓
조건 만족 시 배치
```

Level마다 새로운 배치가 가능하도록 한다.

---

# 13. 먹이 획득

플레이어 지렁이가 먹이에 일정 거리 이내로 접근하면 먹이를 획득한다.

먹이 획득 시:

1. 먹이 제거
2. 먹이 획득 수 증가
3. 지렁이 몸 길이 증가
4. Emoji 진행도 증가
5. 미니맵 업데이트
6. 획득 효과음 재생

예:

```text
먹이 7 / 20
```

---

# 14. 먹이 획득 효과

일반 먹이를 획득할 때 짧은 효과음을 재생한다.

예:

**뿅!**

화면에서도 작은 획득 효과를 적용할 수 있다.

단, 과도한 이펙트로 플레이 화면을 가리지 않도록 한다.

---

# 15. 미니맵

화면 **우측 상단**에 작은 미니맵을 표시한다.

## 15.1 미니맵 목적

넓은 맵에서 플레이어가 현재 위치와 남은 먹이 위치를 확인할 수 있도록 한다.

## 15.2 미니맵 필수 표시

* 전체 맵 영역
* 현재 플레이어 위치
* 남은 먹이 위치
* 획득한 먹이 상태

예:

```text
┌──────────────┐
│ •       •    │
│       🟢     │
│ •            │
│       •      │
│  •       •   │
└──────────────┘
```

🟢 = 플레이어

● = 남은 먹이

---

# 16. 미니맵 업데이트

먹이를 획득하면 해당 먹이의 미니맵 표시도 즉시 변경한다.

예:

```text
20 / 20
```

이 되면 미니맵의 먹이 표시가 모두 사라지고 Emoji 완성 연출로 전환한다.

---

# 17. 적 지렁이

방해물은 일반적인 벽이나 장애물이 아니다.

**플레이어와 유사한 형태의 지렁이**를 사용한다.

적 지렁이는 맵을 이동하며 플레이어의 이동을 방해한다.

플레이어는 적 지렁이와 충돌하지 않으면서 먹이를 찾아야 한다.

---

# 18. Level별 적 지렁이 수

| Level | 적 지렁이 |
| ----: | ----: |
|     1 |     2 |
|     2 |     2 |
|     3 |     3 |
|     4 |     3 |
|     5 |     4 |
|     6 |     5 |
|     7 |     6 |
|     8 |     7 |
|     9 |     8 |
|    10 |    10 |

이 수치는 초기 기본값으로 사용하며, 개발 데이터에서 쉽게 수정할 수 있도록 한다.

---

# 19. 적 지렁이 AI

초기 버전에서는 복잡한 추적 AI를 사용하지 않는다.

기본 AI:

**랜덤 이동 + 일정 시간마다 방향 전환**

으로 구현한다.

## 기본 동작

```text
이동
↓
일정 시간 이동
↓
방향 변경
↓
다시 이동
```

적 지렁이가 플레이어를 계속 추적하는 구조는 초기 버전에서 적용하지 않는다.

향후 난이도 조정에서 필요할 경우 추적 AI를 추가할 수 있도록 구조화한다.

---

# 20. 적 지렁이 이동 속도

적 지렁이 속도는 Level이 올라갈수록 소폭 증가할 수 있도록 설정한다.

단, 초기 기본 난이도에서는 **적 지렁이 수 증가를 가장 중요한 난이도 요소**로 사용한다.

적 속도는 설정값으로 관리한다.

---

# 21. 충돌 시스템

## 21.1 플레이어 ↔ 적 지렁이

충돌하면:

**❤️ 생명 1 감소**

## 21.2 플레이어 ↔ 자신의 몸

자기 몸통과 충돌하면:

**❤️ 생명 1 감소**

## 21.3 플레이어 ↔ 맵 경계

맵 경계와 충돌하면:

**❤️ 생명 1 감소**

---

# 22. 생명 시스템

플레이어의 기본 생명은 **3개**다.

```text
❤️ ❤️ ❤️
```

충돌 1회:

```text
❤️ ❤️
```

충돌 2회:

```text
❤️
```

충돌 3회:

```text
GAME OVER
```

---

# 23. 충돌 후 무적시간

충돌 직후 연속으로 생명이 감소하는 것을 방지하기 위해 **1초간 무적시간**을 적용한다.

게임 흐름:

```text
충돌
↓
생명 -1
↓
1초 무적
↓
정상 상태
```

무적 상태에서는 플레이어 지렁이를 짧게 깜빡이는 방식으로 시각적으로 표시할 수 있다.

---

# 24. GAME OVER

다음 조건에서 게임이 종료된다.

```text
생명 = 0
```

GAME OVER 화면에는 최소한:

* GAME OVER
* 현재 Level
* 획득 먹이 수
* 다시하기
* Level 선택/나가기

를 제공한다.

---

# 25. Emoji 진행 시스템

지렁이 게임의 핵심 보상이다.

먹이를 획득할 때마다 Emoji 그림의 진행도가 증가한다.

예:

```text
1 / 20
2 / 20
3 / 20
...
20 / 20
```

게임 화면 또는 별도의 진행 UI에서 현재 진행 상황을 확인할 수 있다.

---

# 26. Emoji 영역 완성

Emoji 이미지는 여러 영역으로 분할하여 관리한다.

기본적으로 **10개 영역**을 사용한다.

```text
먹이 획득
↓
진행도 증가
↓
Emoji 영역 완성
↓
다음 영역
↓
...
↓
10개 영역 완성
↓
최종 Emoji 완성
```

실제 이미지 분할 방식은 콘텐츠 제작 단계에서 결정하며 게임 로직과 분리한다.

---

# 27. 최종 Emoji 완성

마지막 먹이를 획득하면 최종 Emoji 이미지가 완성된다.

연출:

```text
마지막 먹이 획득
↓
마지막 Emoji 영역 활성화
↓
전체 Emoji 완성
↓
✨ 완성 애니메이션
↓
🎉 LEVEL CLEAR
```

최종 Emoji는 게임 화면 중앙에 크게 표시할 수 있다.

---

# 28. Level Clear

클리어 조건:

**모든 먹이 획득**

예:

```text
20 / 20
```

→ Emoji 완성

→ Level Clear

---

# 29. 클리어 보상

Level을 클리어하면 다음 보상을 제공한다.

## 기본 보상

* 완성된 Emoji 획득
* 별 보상
* 다음 Level 해금

## 별 평가

### ⭐ 1개

Level 클리어

### ⭐⭐ 2개

충돌 1회 이하

### ⭐⭐⭐ 3개

충돌 0회

이 기준은 초기 기본값이며 플레이 테스트 후 조정할 수 있다.

---

# 30. Level 재플레이

이미 클리어한 Level은 다시 플레이할 수 있도록 한다.

재플레이 목적:

* 별 등급 향상
* 3별 도전
* 더 적은 충돌로 클리어
* 자신의 기록 개선

따라서 Level 클리어 후에도 해당 Level을 다시 선택할 수 있어야 한다.

# 32. 난이도 설계 원칙

난이도 상승의 우선순위:

### 1순위

**먹이 수 증가**

20 → 25 → 30 → ... → 65

### 2순위

**적 지렁이 수 증가**

2 → 2 → 3 → ... → 10

### 3순위

필요할 경우:

* 적 지렁이 속도
* 적 지렁이 이동 패턴
* 맵 크기
* 먹이 배치 난이도

를 조정할 수 있다.

단, 플레이어 이동 속도는 기본적으로 고정한다.

# 37. 개발 시 금지사항

다음 사항은 임의로 변경하지 않는다.

* 작은 고정 맵으로 변경하지 않는다.
* 미니맵을 삭제하지 않는다.
* 먹이 수를 임의로 변경하지 않는다.
* Level을 임의로 늘리거나 줄이지 않는다.
* 적 지렁이를 일반 장애물로 변경하지 않는다.
* Emoji 완성 시스템을 제거하지 않는다.
* 플레이어 이동 속도를 임의로 급격하게 증가시키지 않는다.
* 복잡한 적 AI를 초기 버전에 임의로 추가하지 않는다.
* 게임 화면을 과도한 UI로 채우지 않는다.
* 다른 게임의 기능을 지렁이 게임에 임의로 섞지 않는다.

# 40. Claude Code 최종 작업 지시

이 문서를 지렁이 게임의 **최종 기본 개발 명세**로 사용한다.

먼저 현재 프로젝트의 구조와 기존 게임 시스템을 분석한 후, 기존 앱의 다른 게임 및 UI에 영향을 주지 않는 독립적인 지렁이 게임 모듈로 구현한다.

기획서에 명시된 수치는 데이터화하고, 향후 플레이 테스트를 통해 쉽게 수정할 수 있도록 구성한다.

특히 다음 4가지는 지렁이 게임의 핵심 기능이므로 반드시 정상적으로 구현한다.

**① 넓은 맵**

**② 먹이 탐색 + 미니맵**

**③ 적 지렁이 회피**

**④ 모든 먹이 획득 → Emoji 완성**

기능 구현 후 모바일 터치 환경에서 실제 플레이 테스트를 실시하고, 버그 및 조작 문제를 먼저 해결한 뒤 난이도 밸런스를 조정한다.

# 41. Claude 측 결정 사항 (기획서에 위임된 콘텐츠 항목)
