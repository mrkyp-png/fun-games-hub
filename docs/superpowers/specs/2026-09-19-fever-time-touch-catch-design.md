# 두더지팡 — 피버타임(터치캐치 보너스타임) (설계)

**작성일:** 2026-09-19
**대상:** `mole/` (두더지팡)
**한 줄 요약:** 콤보 100 달성(라운드당 1회, 라운드1 제외) 시 20초간 라운드 타이머가 멈추고,
게임보드와 버튼보드(다이얼패드)가 서로 자리를 교차하며 스왑 — 버튼보드는 전광판(콤보·잔여시간
표시)이 되고, 넓어진 게임화면에서 두더지를 직접 터치해 잡는 보너스타임에 들어간다.

---

## 1. 배경 / 문제

`js/game.js`에 이미 "피버" 라는 이름의 기능이 있다(`isFever()`, `SCORE_MULT`) — 콤보 50 이상이면
점수 배율만 조용히 올라가는 버프로, 화면 변화가 없다. 이번에 추가하는 것은 **완전히 별개의 새
기능**이다: 콤보 100 달성 시 화면 전체가 바뀌는 20초짜리 보너스타임 이벤트. 이름이 겹치지만
(사용자 지정 "도파민 극대화" 방향) 화면에 크게 보이는 "FEVER" 연출은 이 새 이벤트가 가져가고,
기존 콤보50 배율은 이름표 없이 배경에서 그대로 계속 작동한다 — **`isFever()`/`SCORE_MULT`는
이 작업에서 손대지 않는다.**

핵심 요구사항(사용자 확정 사항):
- 콤보 100 달성 → 라운드 타이머 정지 → 버튼보드 회전(기존 10바퀴 회전 재사용) → 버튼보드는
  숫자판 대신 전광판(콤보/잔여시간)으로 → 게임보드↔버튼보드 자리 교차 스왑(서로 지나치며
  슬라이드) → 20초간 두더지를 화면 터치로 직접 잡기(무기가 터치한 곳으로 와서 때리는 것처럼
  연출) → 20초 다 채우고(헛방/시간초과로 조기종료 없음) → 역순으로 원위치 → 타이머 재개.
- 라운드1은 제외. **1차 구현/테스트 범위는 라운드2에서만 발동**(사용자 지정: "일단 테스트가
  되어야하니, 라운드2에서만 적용") — 검증 후 라운드3~8까지 넓히는 건 후속 작업. 라운드당 1회만
  발동, 재발동 없음.

## 2. 상태 관리

`state`에 다음 필드 추가:

```
state.feverEventDone      // bool, 이 라운드에서 이미 발동했는지
state.feverEventActive    // bool, 지금 진행 중인지(진입 애니메이션~복귀 애니메이션 전체 구간)
state.feverEventUntil     // performance.now() 기준 종료 타임스탬프 (20초 카운트다운용)
```

`run.combo.combo`를 매 프레임 확인하는 기존 루프(콤보 갱신 직후)에 훅을 추가:

```js
if (!state.feverEventDone && run.combo.combo >= 100
    && currentChapter() === 2) {  // 1차 테스트 범위: 라운드2만 (사용자 지정)
  startFeverEvent();
}
```

`startFeverEvent()`가 하는 일:
1. `state.feverEventDone = true; state.feverEventActive = true;`
2. 라운드 타이머 정지 — 기존 `state.paused` 재사용이 아니라 **별도 플래그**
   `state.pausedByFever = true`로 둔다(더보기 메뉴의 `pausedByMenu`와 동일한 패턴, 서로 다른
   정지 사유를 구분해야 나중에 "더보기 열림+피버 동시" 같은 엣지케이스에서 안전).
3. `state.feverEventUntil = performance.now() + 20000`.
4. 진입 연출 시작(§3) → 연출 끝나면 실제 20초 카운트다운 시작.
5. 20초 뒤 복귀 연출(§5) → 끝나면 `state.pausedByFever = false`로 타이머 재개.

메인 루프(`loop()`)의 시간 감소 로직은 `if (!state.paused && !state.pausedByFever)` 조건을
추가해 피버 중 시간이 안 줄게 한다.

## 3. 진입 연출

1. 버튼보드(`#lane-button-bar`) 전체에 기존 `spinChannelsIn()`(`lane-controls.js`, rotateY
   3600°, 10바퀴, perspective 600px, 0.9s cubic-bezier, 단면이라 앞면 유지)과 **동일한 방식의
   회전**을 재사용해서 건다. 회전이 끝나는 시점에 버튼보드 내용을 숫자/아이콘 그리드 대신
   "전광판" 뷰로 교체(§4).
2. 회전과 동시에(또는 회전 종료 직후 — 실기기 확인 후 타이밍 결정) `#mole-board`(게임보드)와
   `#lane-button-bar`(버튼보드)가 서로의 자리로 교차 슬라이드:
   - 두 요소의 현재 `getBoundingClientRect()`를 읽어 서로의 top 차이만큼
     `transform: translateY()`를 반대 방향으로 적용 (FLIP 기법 — 착지 캡슐 위치 계산과 같은
     패턴, `shop.js`의 `getBoundingClientRect()`+`offsetWidth/Height` 안정화 노하우 재사용).
   - 애니메이션 종료 후 실제 DOM 순서/CSS 순서를 스왑(또는 `order` 스타일 스왑)해 이후
     레이아웃 계산이 트랜스폼 없이도 올바른 위치를 갖게 정리.
3. 진입 연출 총 소요시간은 20초 카운트다운에 포함하지 않는다(카운트다운은 전광판이 뜬 뒤 시작).

## 4. 피버타임 진행 (20초)

**전광판(버튼보드 자리, 사용자 지정 "전광판처럼 콤보 표기, 남은 타임 표기"):**
- 큰 숫자로 잔여 초(20→0) 카운트다운.
- 콤보 수치 실시간 표기(기존 `run.combo.combo`를 매 프레임 반영).
- 스타일은 기존 `#invincible-countdown`(알리펀치 무적 카운트다운) 패턴 참고 — 새 엘리먼트/클래스로.

**두더지 스폰/타격 (게임보드 자리, 넓어진 화면):**
- 두더지 스폰 로직(`spawn-scheduler.js`)은 그대로 재사용 — 기존 구멍 그리드 그대로.
- 입력 방식만 변경: 평소엔 "다이얼패드의 올바른 셀을 눌러야" 타격 판정이 나지만, 피버 중엔
  **게임보드 위 아무 곳이나 터치 → 그 좌표에 해당하는 구멍(regionId) 판정 → 명중 처리**.
  `handleCell`을 거치지 않는 새 입력 경로가 필요(다이얼패드가 화면에 없으므로 셀 개념 자체가
  없음) — 터치 좌표를 보드의 구멍 그리드 좌표로 역산하는 함수 신규 작성.
- 명중 시 시각 연출(사용자 지정: "터치한곳은 무기가 와서 때리는것 같이") — 기존
  `state.laneHammer.strike(targetXFrac, targetYFrac, onImpact, frameKey, regionId)` API
  (2026-09-17 멀티터치 스펙에서 이미 풀(pool) 래퍼로 구현됨, `targetXFrac/targetYFrac` 인자를
  이미 받으므로 임의 좌표 타격에 그대로 재사용 가능)를 터치 좌표로 호출.
- 콤보/점수는 기존 `run.combo.hit()`/`miss()` 그대로 — 콤보50 배율(`SCORE_MULT`)도 자연히
  계속 적용됨. 헛방(빈 곳 터치, 시간초과로 두더지 사라짐)이 나도 20초 타이머·연출은 계속.

---

## 5. 종료(복귀) 연출

§3의 정확한 역순: 게임보드/버튼보드 교차 슬라이드로 원위치 → 버튼보드 10바퀴 역회전(또는 같은
방향 10바퀴 추가 회전, 실기기 확인 후 결정)으로 숫자판 복귀 → `state.pausedByFever = false` →
라운드 타이머 재개.

## 6. 건드릴 파일

- `js/game.js` — 트리거 훅, `state.feverEvent*` 필드, `startFeverEvent()`/복귀 함수, 메인루프
  타이머 정지 조건, 터치→구멍 좌표 역산 입력 핸들러.
- `js/lane-controls.js` — 버튼보드 회전 트리거를 외부에서 호출 가능하게(기존
  `spinChannelsIn()`이 내부 전용이면 노출), 전광판 뷰 렌더링.
- `style.css` — 교차 슬라이드 트랜지션, 전광판(`.fever-board` 류) 스타일, 피버 중 게임보드
  글로우/테두리 등 부가 연출(있다면).
- `js/i18n-strings.js` — "FEVER!" 관련 문구(있다면).
- 무기 모듈(`lane-hammer.js`/`lane-cannon.js`/`lane-boxing.js`)·`hit-fx.js`: **수정 없음** —
  기존 `strike()` 인터페이스를 좌표만 바꿔 그대로 호출.

## 7. 범위 밖 (이번엔 안 함)

- 콤보50 배율 피버(`isFever()`)와의 통합/이름 통일 — 그대로 둔다.
- 무기별(뿅망치/골드해머/캐논/알리판취) 피버 전용 특수 연출 — 기존 `strike()` 그대로, 무기별
  차별화 없음.
- 사운드/BGM 전환 — 이번 스펙엔 미포함, 필요하면 구현 중 별도 확인.
